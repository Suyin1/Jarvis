# CEF 桌面应用迁移到 HarmonyOS PC 架构设计文档

## 概述

本文档描述两套示例工程的架构设计方案，用于将基于 CEF 框架开发的桌面应用迁移到 HarmonyOS PC 平台：

1. **纯 CEF + ArkTS 架构** — CEF 浏览器直接嵌入 ArkTS/XComponent
2. **CEF + QT + ArkTS 架构** — CEF 通过 QT Widget 桥接嵌入 ArkTS/XComponent

两种架构均以 ArkTS 作为应用入口，以 CEF 渲染 Web 页面，通过 JsBinding 机制调用 HarmonyOS 原生 API。

> **读者对象**：本工程作为客户参考示例，客户有自己的纯 CEF+ArkTS 工程和 CEF+QT+ArkTS 工程，期望通过 AI Agent 参考本工程的设计和实现，将同样的桥接思路迁移至他们自己的工程中。

## 代码库架构（.so 库关系）

本工程的 C++ 代码编译为 3 个独立的共享库，理解它们的关系是桥接层设计的关键：

```
libadapter_c.so  ───  NAPI 导出 ───→  ArkTS 可直接调用
  (adapter_c.cpp)      函数: initFunc, getWindowNameByXComponentId

libcefsimple.so  ─── 链接──→  libadapter.so (预编译)
  (testcef/*.cpp)        ↑ libadapter.so 提供 JSBind.bindFunction()
                          ↑ 供 ArkTS 注册函数到 C++

libqtmodule.so   ─── 链接──→  libcefsimple.so + libadapter_c.so
  (main.cpp,             ↑ qtmodule 可访问 TCSimpleHandler + adapter_c
   mainwindow/*.cpp)
```

| 库 | 来源 | 能否修改 | 提供能力 |
|---|------|---------|---------|
| `libadapter.so` | 预编译二进制 | ❌ 不能改 | `JSBind.bindFunction()` — ArkTS 函数注册到 C++ 的机制 |
| `libadapter_c.so` | `ohos/adapter_c/adapter_c.cpp` | ✅ 可改 | ArkUI FrameNode 管理 + NAPI 导出 |
| `libcefsimple.so` | `testcef/*.cpp` | ✅ 可改 | CEF Handler/App/Render + 消息路由 |
| `libqtmodule.so` | `main.cpp` + `mainwindow/*` | ✅ 可改 | Qt 应用入口 + 窗口管理 |

### 两个 CEF 架构的模块分布

```
web_engine/ (项目根目录，与 entry/ 同级)  ← 原始源码
  ├── adapter/   (44 适配器)
  ├── jsbindings/(43 JsBinding)
  ├── ability/   (WebAbility, WebBaseAbility, WebQtAbility)
  ├── common/
  ├── interface/
  ├── components/
  ├── utils/
  └── process/

entry/oh_modules/web_engine/             ← 依赖安装副本（不可直接修改）
  └── (同上结构，由构建系统从 web_engine/ 链接过来)

entry/src/main/cpp/                      ← C++ 层（共用）
  ├── testcef/                           ← 纯 CEF 核心 (cefsimple)
  ├── ohos/adapter_c/                    ← ArkUI 节点适配器 (adapter_c)
  ├── main.cpp                           ← QT 应用入口 (qtmodule)
  └── mainwindow/                        ← QT 窗口管理 (qtmodule)
```

> **注意**：`entry/oh_modules/web_engine/` 是 `web_engine/` 依赖安装后的副本（类似 npm `node_modules`），
> **不应直接编辑 `entry/oh_modules/web_engine/` 中的文件**。所有修改应基于项目根目录的 `web_engine/` 原始源码。
>
> 关联方式：`entry/oh-package.json5` 中声明 `"web_engine": "file:../web_engine"`，构建系统将其链接到 `oh_modules`。

### 1.2 启动流程

```

  └─ adapter_c.initFunc()        // 初始化 C 适配器
```

### 1.3 页面实现方案

#### 1.3.1 页面类型

| 页面类型 | 渲染方式 | 实现说明 |
|---------|---------|---------|
| Web 页面 (首页/登录页/协议页等) | CEF 渲染 | 在 XComponent 中加载 URL，由 CEF 完全控制渲染 |
| 原生页面 (一键登录/个人中心) | ArkTS 组件 | 使用 NavPathStack + NavDestination 构建纯 ArkTS 页面 |
| 混合页面 | CEF + ArkTS 叠加 | CEF 渲染 Web 内容 + ArkTS 原生组件浮层叠加 |

#### 1.3.2 页面跳转方案

**方案 A：全部在 CEF 内跳转**

所有页面均为 Web H5 页面，通过 CEF 的 URL 加载/后退/前进管理导航。

```
Index.ets (XComponent)
  └─ CEF Browser
       ├─ 首页 (加载 url_a)
       ├─ 登录页 (加载 url_b)
       ├─ 协议页 (加载 url_c)
       └─ 个人中心 (加载 url_d)
```

- 优点：纯 Web 开发，快速迁移
- 缺点：无法使用 ArkTS 原生组件（如一键登录按钮）

**方案 B：ArkTS 原生页面 + CEF Web 页面混合**

使用 ArkTS `NavPathStack` 作为页面路由，关键页面用 ArkTS 原生实现。

```
┌─────────────────────────────────────────┐
│              Index.ets                   │
│  ┌─────────────────────────────────────┐│
│  │  NavPathStack 路由栈                ││
│  │  ┌──────────┐                      ││
│  │  │首页(CEF) │ ← XComponent 全屏     ││
│  │  └──────────┘                      ││
│  │  ┌──────────┐                      ││
│  │  │登录(混合) │ ← CEF Web + ArkTS 浮层││
│  │  └──────────┘                      ││
│  │  ┌──────────┐                      ││
│  │  │一键登录   │ ← 纯 ArkTS 页面      ││
│  │  └──────────┘                      ││
│  └─────────────────────────────────────┘│
└─────────────────────────────────────────┘
```

### 2.3 关键组件说明

#### 2.3.1 Qt 角色

在本架构中，Qt 充当**中间渲染和事件处理层**：

| 功能 | 说明 |
|------|------|
| 窗口管理 | QMainWindow 管理 CEF 浏览器的尺寸/位置 |
| 事件循环 | 处理鼠标/键盘/触摸事件，转发到 CEF |
| 渲染桥接 | QWindow 通过 FrameNode 嵌入到 ArkUI 渲染树 |
| 子窗口 | 管理 CEF 弹出窗口 (NewWindow) 的创建 |
| UI 控件 | 可提供地址栏/工具栏等原生 UI 控件 |

#### 2.3.2 Qt 多窗口支持

```
Qt 主窗口 (MainWindow)
  ├─ CEF 浏览器 (CefBrowser)     ← 主 Web 页面
  ├─ CEF 弹出窗口 (NewWindow)    ← target=_blank 弹窗
  └─ 测试对话框 (TestDialog)     ← JS 调用测试窗口
```

每个 Qt 窗口通过 adapter_c 创建一个对应的 FrameNode，嵌入到 ArkUI 树。

### 2.4 页面实现方案

同纯 CEF + ArkTS 架构的页面方案（1.3 节），区别在于：

1. **CEF 浏览器由 Qt 管理** — 页面 URL 加载、窗口大小由 MainWindow 控制
2. **ArkTS 原生页面作为独立 Ability** — 可启动单独的 EntryAbility 运行 ArkTS 页面
3. **页面间通信** — CEF ↔ Qt ↔ adapter_c ↔ ArkTS (通过 JsBinding)

#### 2.4.1 混合导航示例

本工程采用 **V8 扩展方式**实现 HTML ↔ ArkTS 双向导航，而非自定义 scheme 拦截方式。
V8 扩展方式已经在 `TCSimpleRenderDelegate.h` 中注入了 `ClientAPI` 对象到每个 Web 页面，
基础设施已经就位。

```
// 场景：用户在 CEF Web 页面点击"一键登录"按钮 → 跳转 ArkTS 原生页面

// Step 1: Web 页面 JS 调用已注入的 V8 扩展函数
window.ClientAPI.navigateToNative('OneKeyLogin', callback);

// Step 2: MyCefV8Handler::Execute() 拦截 V8 调用
// → 发送跨进程消息到浏览器进程
// → SendProcessMessage("CallBackFunction", {name, param, callback_id})

// Step 3: TCSimpleHandler::OnProcessMessageReceived 接收消息
// → 识别 navigateToNative 命令

// Step 4: 通过 adapter_c 的 NAPI 回调机制调用 ArkTS 注册的函数
// → adapter_c.navigateCallback(pageName)

// Step 5: ArkTS NavigationBind.ets 处理回调
// → JsBindingUtils.bindFunction('navigateToNative', (page) => {
//     router.pushUrl({ url: `pages/${page}` })
//   })
```

```
// 场景反向：ArkTS 原生页面 → CEF HTML 页面

// Step 1: ArkTS 调用 adapter_c 的 NAPI 导出
adapter_c.cefLoadUrl('html/profile.html')

// Step 2: C++ NAPI 函数通过函数指针桥 → qtmodule
// → MainWindow::LoadURL(url)

// Step 3: CEF 加载 HTML 页面
// → CefBrowserHost::GetBrowser()->GetMainFrame()->LoadURL(url)
```

#### 2.4.2 两种方案对比

| 维度 | V8 扩展方式（选用） | Custom Scheme 方式（备选） |
|------|-------------------|-------------------------|
| 触发方式 | `window.ClientAPI.xxx()` 函数调用 | `location.href = 'myapp://xxx'` 导航 |
| HTML 端写法 | JS 函数调用，可传参和回调 | URL 字符串，参数受限 |
| 当前基础设施 | ✅ V8 扩展已注入 + MyCefV8Handler 就绪 | ❌ OnBeforeBrowse 未实现 |
| 额外开发量 | 加函数 + 处理消息 + 注册 ArkTS 回调 | 实现 CefRequestHandler + 注册 scheme + 处理消息 |
| 推荐度 | ⭐ 首选 | 次选 |

#### 2.4.3 与纯 CEF 架构的核心差异

| 维度 | 纯 CEF + ArkTS | CEF + QT + ArkTS |
|------|---------------|------------------|
| 浏览器管理 | 直接 CEF API | 通过 QMainWindow 间接管理 |
| 事件循环 | CEF 自有循环 | Qt QApplication::exec() |
| UI 控件 | 需 ArkTS 实现 | 可用 Qt Widget 实现 |
| 多窗口 | 需自行管理 | Qt 原生支持 |
| 迁移成本 | 低 (纯 Web) | 中 (需适配 Qt) |
| 与 ArkTS 融合 | 紧密 | 需通过 C++ 桥接 |

### 3.1 路由栈结构

```
NavPathStack (全局路由栈)
  ├─ 首页        (CEF Web Page / type=cef)
  ├─ 详情页      (CEF Web Page / type=cef)
  ├─ 协议页      (CEF Web Page / type=cef)
  ├─ 手机号登录页 (ArkTS Native / type=arkts)
  └─ 一键登录页   (ArkTS Native / type=arkts)
```

### 3.2 路由跳转矩阵

| 从/到 | ArkTS 原生页 | CEF Web 页 |
|-------|-------------|-----------|
| **ArkTS 原生页** | NavPathStack.pushPath() | NavPathStack.pushPath() + XComponent 显示/加载 URL |
| **CEF Web 页** | JsBinding 调用 → pushPath() | window.location / CEF 导航 |

### 3.3 最佳实践建议

1. **关键鉴权页面使用 ArkTS 原生** — 一键登录、华为账号登录等需要 HuaweiID SDK 的页面
2. **内容展示页面使用 CEF Web** — 首页、协议页、个人中心等 H5 页面
3. **页面间通信统一走 JsBinding** — 避免 ArkTS ↔ CEF 直接耦合
4. **按需选择架构** — 如果已有 QT 代码/需要复杂桌面窗口管理 → CEF+QT+ArkTS；否则优先纯 CEF+ArkTS

## 四、JsBinding 桥接机制（当前实际架构）

### 4.1 已有的两个独立桥接通道

本工程实际上有两个独立的桥接通道，用途不同：

```
通道1: JsBinding (ArkTS → C++ 函数注册)
┌──────────────────┐  bindFunction()  ┌──────────────────┐
│  JsBindingUtils   │ ──────────────►  │  libadapter.so   │
│  .ets             │ 注册函数名+指针   │  (预编译)         │
│                   │                  │  存储函数引用      │
│  DisplayBind      │                  │  供 C++ 后续调用   │
│  BluetoothBind    │                  │                   │
│  (43个)           │                  │                   │
└──────────────────┘                  └──────────────────┘
用途: 设备能力适配器 (显示/蓝牙/电量等) 注册给 C++ 调用

通道2: V8 扩展 (CEF JS → C++ 消息)
┌──────────────────┐  V8 Execute()   ┌──────────────────┐
│  HTML 页面        │ ──────────────►  │  MyCefV8Handler  │
│                   │                  │  (渲染进程)       │
│  window.ClientAPI │                  │                   │
│  .showMsg()      │                  │ SendProcessMessage│
│                   │                  │       ↓           │
│                   │                  │ TCSimpleHandler   │
│                   │                  │ (浏览器进程)       │
└──────────────────┘                  └──────────────────┘
用途: Web 页面 JS 调用 C++ 功能 (消息路由)
```

### 4.2 V8 扩展注入详情

已在 `TCSimpleRenderDelegate.h` 中实现：

```cpp
// 每个 Web 页面加载时自动注入
std::string app_code = R"(
    var ClientAPI = {};
    (() => {
        ClientAPI.showMsg = function(v1, v2) {
            native function showMsg(v1, v2);
            return showMsg(v1, v2);
        };                        
    })();
)";
CefRegisterExtension("v8/extern", app_code, m_pV8handler);
```

`MyCefV8Handler` 接收 V8 调用 → 序列化为 `CallBackFunction` 跨进程消息 → 发给浏览器进程的 `TCSimpleHandler::OnProcessMessageReceived`。

### 4.3 已实现的导航桥接

两个通道已经通过 CefBridge 桥接层打通：

```
CEF JS → C++ (通道2已有) → navigate_callback_ (静态函数指针)
  → adapter_c::navigate_bridge_ (函数指针)
  → uv_queue_work → napi_call_function
  → ArkTS NavigationBind.ets → router.pushUrl()

ArkTS → CEF URL 加载 (通道1 + NAPI)
  → adapter_c.cefLoadUrl()
  → load_url_bridge_ (函数指针)
  → CefBridge::LoadURL()
  → TCSimpleHandler::LoadURL()
```

## 六、桥接层实现方案（✅ 已实现）

### 5.1 总体方案：V8 扩展方式

利用已存在的 `ClientAPI` V8 扩展 + `MyCefV8Handler` 消息路由 + `adapter_c` NAPI 导出，
构建完整的 HTML ↔ ArkTS 双向导航通道。

### 5.2 实现步骤

#### Step 1: V8 扩展添加导航函数 ✅

**文件**: `TCSimpleRenderDelegate.h` — `OnWebKitInitialized()` 中的 `app_code`

`ClientAPI.navigateToNative` 已添加到 V8 app_code 中，HTML 页面可直接调用 `window.ClientAPI.navigateToNative('OneKeyLogin', callback)`，

由 `MyCefV8Handler::Execute` 拦截并发送 `CallBackFunction` 跨进程消息给浏览器进程。

#### Step 2: TCSimpleHandler 处理导航消息 ✅

**文件**: `TCSimpleHandler.h` — 添加静态函数指针 `navigate_callback_` 和 `SetNavigateCallback`

```cpp
// 导航回调函数指针 —— 由 qtmodule（mainwindow）启动时设置，桥接到 ArkTS
typedef void (*NavigateCallback)(const std::string &pageName, int js_callback_id,
                                 CefRefPtr<CefBrowser> browser, CefRefPtr<CefFrame> frame);
static NavigateCallback navigate_callback_;
static void SetNavigateCallback(NavigateCallback cb) { navigate_callback_ = cb; }
```

**文件**: `TCSimpleHandler.cpp` — `ExecuteCallbackFunc` 中处理 `navigateToNative`

```cpp
} else if (function_name == "navigateToNative") {
    LOG(INFO) << "navigateToNative params: " << params;
    if (navigate_callback_) {
        navigate_callback_(params.ToString(), js_callback_id, browser, frame);
    }
}
```

用静态函数指针而非直接调 `adapter_c` 的原因是：`cefsimple.so` 不链接 `adapter_c.so`，不能直接调用其函数。
由 `qtmodule.so`（mainwindow，同时链接两者）在启动时通过 `SetNavigateCallback` 注入函数指针。

#### Step 3: adapter_c 添加 NAPI 回调注册和调用 ✅

**adapter_c.h** 新增了三个桥接点：

```cpp
// 函数指针桥（由 mainwindow 设置）
typedef void (*NavigateBridge)(const std::string &pageName);
static NavigateBridge navigate_bridge_;
static void SetNavigateBridge(NavigateBridge cb);

typedef void (*LoadUrlBridge)(const std::string &url);
static LoadUrlBridge load_url_bridge_;
static void SetLoadUrlBridge(LoadUrlBridge cb);

// NAPI 引用 — 供 C++ 侧调用 ArkTS 注册的函数
static napi_ref arkts_navigate_ref_;

```

**adapter_c.cpp** 中的关键实现：

- `DefaultNavigateBridge` — navigate_bridge_ 的默认实现，通过 uv_queue_work 切换到 JS 线程，用 `arkts_navigate_ref_` 调用 ArkTS 注册的函数
- `navigate_bridge_` 在 `EWAdapterC::init` 时自动设置为 `DefaultNavigateBridge`
- `registerNavigateCallback` — NAPI 导出，供 `NavigationBind.ets` 注册 ArkTS 导航回调
- `navigateToNative` — NAPI 导出，ArkTS 可手动调用触发原生页面跳转（调试用）
- `cefLoadUrl` — NAPI 导出，ArkTS 调用以加载 CEF 中的指定 URL，桥接到 `load_url_bridge_`

```cpp
// NAPI 导出注册
napi_property_descriptor desc[] = {
    {"initFunc", 0, InitFunc, 0, 0, 0, napi_default, 0},
    {"getWindowNameByXComponentId", 0, GetWindowNameByXComponentId, 0, 0, 0, napi_default, 0},
    {"navigateToNative", 0, NavigateToNative, 0, 0, 0, napi_default, 0},
    {"cefLoadUrl", 0, CefLoadUrl, 0, 0, 0, napi_default, 0},
    {"registerNavigateCallback", 0, RegisterNavigateCallback, 0, 0, 0, napi_default, 0},
};
```

#### Step 4: CefBridge 注册导航回调桥 ✅

**文件**: `cef_bridge/CefBridge.cpp` — `RegisterBridges()` 方法

本工程在 `CefBridge` 中注册两个方向的桥接，由 ArkTS 侧 `adapter_c.cefInit()` 触发。
无需 Qt 中间层，`CefBridge` 直接链接 `testcef` 和 `adapter_c` 两者：

```cpp
void CefBridge::RegisterBridges() {
    // 方向 A: CEF JS → ArkTS（TCSimpleHandler → adapter_c → NAPI → ArkTS）
    TCSimpleHandler::SetNavigateCallback(
    [](const std::string &pageName, int js_callback_id,
           CefRefPtr<CefBrowser> browser, CefRefPtr<CefFrame> frame) {
        if (EMBEDDED_WINDOW_ADAPTER::EWAdapterC::navigate_bridge_) {
            EMBEDDED_WINDOW_ADAPTER::EWAdapterC::navigate_bridge_(pageName);
        }
        // 回调 JS（通过 ExecutedCallbackToJS 消息告知渲染进程）
        CefRefPtr<CefProcessMessage> msg = CefProcessMessage::Create("ExecutedCallbackToJS");
        msg->GetArgumentList()->SetInt(0, js_callback_id);
        msg->GetArgumentList()->SetInt(1, 0);
        msg->GetArgumentList()->SetString(2, R"({"code":0,"msg":"ok"})");
        frame->SendProcessMessage(PID_RENDERER, msg);
    });

// 方向 B: ArkTS → CEF URL 加载（adapter_c NAPI → CefBridge → CEF）
EMBEDDED_WINDOW_ADAPTER::EWAdapterC::SetLoadUrlBridge(
    [](const std::string &url) {
        CefBridge::GetInstance()->LoadURL(url);
    });
}
```

用静态函数指针而非直接调用的原因是：`cefsimple.so` 不链接 `adapter_c.so`，不能直接调用其函数。
由 `CefBridge`（编译入 `libcefsimple.so`，同时链接 `adapter_c`）在初始化时通过 `SetNavigateCallback` 注入函数指针。

#### Step 4b: ArkTS 触发 CEF 初始化 ✅

纯 CEF 架构中，CEF 生命周期完全由 ArkTS 通过 NAPI 导出触发，无需 C++ 入口（无 main.cpp）：

**文件**: `entry/src/main/ets/Application/AbilityStage.ets`

```typescript
// MyAbilityStage.onCreate()
adapter_c.initFunc(scaledDensity);    // 初始化 adapter_c 函数表
adapter_c.cefInit();                  // → CefBridge::RegisterBridges() + StartCef()
```

**文件**: `entry/src/main/ets/pages/Index.ets`

```typescript
XComponent({ id: this.windowId, type: XComponentType.SURFACE })
  .onLoad((context) => {
    adapter_c.cefSurfaceReady(this.windowId, context);
    // → CefBridge::OnSurfaceReady() → CreateBrowser()
  })
```

两个关键的 NAPI 导出（`adapter_c.cpp`）：

| NAPI 函数 | 调用时机 | 行为 |
|-----------|---------|------|
| `cefInit` | `AbilityStage.onCreate()` | `CefBridge::RegisterBridges()` + `CefBridge::StartCef()` |
| `cefSurfaceReady` | `XComponent.onLoad()` | `CefBridge::OnSurfaceReady()` → `CreateBrowser(surfaceHandle)` |

#### Step 5: ArkTS 注册导航回调 ✅（已完善）

**文件**: `web_engine/src/main/ets/jsbindings/NavigationBind.ets`

注册 ArkTS 导航回调到 C++ 层。不是通过 `JsBindingUtils.bindFunction`，而是通过 `adapter_c.registerNavigateCallback` NAPI 导出：

```typescript
import adapter_c from 'libadapter_c.so';
import router from '@ohos.router';

export class NavigationBind {
  static bind() {
    adapter_c.registerNavigateCallback((pageName: string) => {
      console.info(`NavigationBind: navigate to native page: ${pageName}`);
      try {
        router.pushUrl({
          url: `pages/${pageName}`,
          params: { source: 'cef_html' }
        });
      } catch (err) {
        console.error(`NavigationBind: pushUrl failed for ${pageName}: ${err}`);
      }
    });
  }
}
```

在 `JsBindingMethod.ets` 中添加 `NavigationBind.bind()` 调用。

> 当 CEF HTML 中 `window.ClientAPI.navigateToNative('OneKeyLogin', callback)` 调用时，
> 经过完整链路最终调用此回调，`router.pushUrl` 将导航到 `pages/OneKeyLogin.ets` 页面。
> `pages/` 页面需在 `main_pages.json` 中注册（已添加 `OneKeyLogin` 和 `HomePage`）。

## 八、QT 剥离指南（构建纯 CEF+ArkTS）

如需要从本工程剥离 QT 获得纯 CEF+ArkTS 版本：

### 8.1 QT 涉及的内容

| 文件/模块 | 内容 | 是否必须 |
|-----------|------|---------|
| `main.cpp` | Qt `QApplication` 入口 | 移除 |
| `mainwindow/mainwindow.cpp/h` | `QMainWindow` + CEF 管理 | 移除 |
| `mainwindow/newwindow.cpp/h` | Qt 标签式子窗口 | 移除 |
| `mainwindow/testdialog.cpp/h` | Qt 测试对话框 | 移除 |
| `CMakeLists.txt` 中 `qtmodule` | Qt 库编译和链接 | 移除 |
| `entry/src/main/ets/entryability/EntryAbility.ets` | 继承 `WebQtAbility` | 改为继承 `WebAbility` |
| `web_engine/` 根目录模块 | `WebQtAbility.ets` | 可选移除 |

### 8.2 保留不变的内容

| 文件/模块 | 说明 |
|-----------|------|
| `testcef/*` | CEF 核心逻辑，不依赖 QT |
| `ohos/adapter_c/*` | ArkUI 节点适配器，不依赖 QT |
| `web_engine/` (根目录) | 纯 CEF ArkTS 模块，不依赖 QT |
| `libadapter.so` | JsBinding 预编译库，不依赖 QT |

### 8.3 接入方式差异

| 维度 | CEF+QT+ArkTS | 纯 CEF+ArkTS |
|------|-------------|-------------|
| 页面容器 | `XComponent(type: NODE)` + QPA | `XComponent(type: Surface)` 直接渲染 |
| CEF 初始化 | Qt 线程中 `CefInitialize` | ArkTS 生命周期中直接调用 |
| 事件处理 | Qt 事件循环转发 | CEF 自有事件循环 |
| 多窗口 | Qt `NewWindow` | ArkTS `AbilityManager` 管理 |
