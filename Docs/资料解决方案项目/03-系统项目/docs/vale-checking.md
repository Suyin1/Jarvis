# Vale Checking Integration

> How Vale is used for document quality checking in the Doc Solution System

---

## What is Vale

[Vale](https://vale.sh) is a standalone, open-source documentation linter. It checks Markdown files against configurable style rules for grammar, style, terminology, and readability.

In the Doc Solution System, Vale serves as the **style and format checking backend**. It is optional -- the system degrades gracefully when Vale is not installed.

## How Vale is Integrated

### Architecture

```
+-------------------+     Vale JSON output      +-------------------+
|  ValeAdapter      | ------------------------> |  CheckReport      |
|  (Python wrapper) |     parsed alerts         |  (unified format) |
+-------------------+                           +-------------------+
         |                                                ^
         | vale CLI --output json                         |
         v                                                |
+-------------------+                                    |
|  vale binary      |     Optional: installed via npm     |
|  (vale.exe)       |     or downloaded from vale.sh     |
+-------------------+
```

The integration is in `engine/rule_engine/vale_adapter.py`:

### ValeAdapter Class

```python
class ValeAdapter:
    def __init__(self, config: ValeConfig):
        # config.vale_bin: path to vale executable (default: "vale")
        # config.config_path: path to .vale.ini (optional)

    def check(self, target: str) -> ValeResult:
        # 1. Validate target path exists
        # 2. Build vale CLI command
        # 3. Execute: vale --output JSON <target>
        # 4. Parse JSON output into ValeResult
        # 5. Return structured result
```

### Graceful Degradation

When Vale is not installed:

1. `ValeAdapter.check()` detects vale CLI not found
2. Returns `ValeResult` with `exit_code = -1` and error message
3. `tools/check.py` converts this to a `ReportItem` with severity `warning`
4. System continues with structure and format checks
5. No crash, no interruption

## Vale Configuration

### Default Configuration

The default Vale config (`knowledge/rules/vale/.vale.ini`):

```ini
StylesPath = styles
MinAlertLevel = suggestion

[*.md]
BasedOnStyles = DocsStyle, Custom

[DocsStyle]
HeadingHierarchy = YES
SentenceLength = YES

[Custom]
Terminology = YES
```

### Generated Configuration

When `build-kb` is run, it generates a customer-specific Vale configuration:

```ini
; Vale Configuration - CustomerName
; Generated by Doc Solution Knowledge Builder

StylesPath = styles
MinAlertLevel = suggestion

[*.md]
BasedOnStyles = DocsStyle, Custom

[DocsStyle]
HeadingHierarchy = YES
SentenceLength = YES

[Custom]
Terminology = YES
```

## Vale Rules in the System

### Built-in Rules (`knowledge/rules/vale/styles/`)

#### DocsStyle/HeadingHierarchy.yml

```yaml
extends: existence
message: "Heading level should use '#' markers"
level: warning
scope: heading
nonword: true
tokens:
  - '#+ '
```

#### Custom/Terminology.yml

```yaml
extends: conditional
message: "Term '%s' may not follow convention"
level: suggestion
scope: text
ignorecase: true
first: '\\b(API|SDK|UI|JSON|YAML|CLI|REST|HTTP|SSH|MCP)\\b'
second: ''
action:
  name: replace
  params:
    - API
    - API
```

### Adding Custom Rules

Place custom Vale rules in `knowledge/rules/vale/styles/`:

```
knowledge/rules/vale/styles/
  |-- DocsStyle/
  |   |-- HeadingHierarchy.yml
  |   +-- SentenceLength.yml
  |-- Custom/
  |   |-- Terminology.yml
  |   +-- BrandName.yml
  +-- YourOrg/
      +-- YourRule.yml
```

Then reference them in `.vale.ini`:

```ini
[*.md]
BasedOnStyles = DocsStyle, Custom, YourOrg
```

## Check Types and Vale

The `check` command integrates Vale based on the `--check-type` parameter:

| --check-type | Vale Used? | Description |
|-------------|-----------|-------------|
| `structure` | No | Heading hierarchy, required sections |
| `format` | Yes | Vale style checks + built-in format checks (paragraph length, code blocks) |
| `style` | Yes | Vale style checks only |
| `all` | Yes | Everything: structure + format + style |

## Running Vale Checks

### Via CLI

```bash
# Full check with Vale
doc-solution check --target ./docs/ --check-type all

# Style check only (uses Vale)
doc-solution check --target ./docs/ --check-type style

# Format check (uses Vale + built-in)
doc-solution check --target ./docs/ --check-type format

# Custom Vale config
doc-solution check --target ./docs/ --config ./custom/.vale.ini
```

### Via MCP

The `quality_check` MCP tool supports the same parameters:

```json
{
  "name": "quality_check",
  "arguments": {
    "target": "./docs/",
    "check_type": "all",
    "vale_bin": "vale",
    "config_path": "./custom/.vale.ini"
  }
}
```

### Vale JSON Output

Vale outputs JSON which the adapter parses:

```json
{
  "test.md": {
    "alerts": [
      {
        "Line": 1,
        "Column": 1,
        "Severity": "warning",
        "Message": "Use 'API' instead of 'api'.",
        "Check": "Custom.Terminology",
        "Match": "api"
      }
    ]
  }
}
```

This is converted to the system's `CheckReport` format by `ValeAdapter`.

## Installing Vale

Vale can be installed via npm (already available in this environment):

```bash
npm install -g @errata-ai/vale
```

Or download from [vale.sh/releases](https://github.com/errata-ai/vale/releases).

Verify installation:

```bash
vale --version
```

## Troubleshooting

### Vale not found

If Vale is not installed, the system shows:

```
[?] [needs_review] Vale is not available. Install: npm install -g @errata-ai/vale
```

The check continues with structure and format checks.

### Vale config not found

If the `.vale.ini` path is incorrect:

```
[?] [needs_review] Vale config not found: ./path/to/.vale.ini
```

Specify the correct path with `--config`.

### Vale JSON parse error

If Vale outputs unexpected format, the adapter returns the error message and continues.
