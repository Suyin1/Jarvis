## 一、产品概述

### 1.1 产品定位

面向大型企业（如华为、苹果、谷歌、腾讯、阿里巴巴等）的开发者资料团队，提供一套**全流程、可定制、AI友好的资料解决方案系统**。该系统覆盖资料开发、测试、维护、问题解决全链路，通过AI Agent驱动，实现资料工作的标准化、自动化、智能化，达到**提升效率、解放人力**的目标。

### 1.2 目标用户

| 用户角色 | 职责 | 关注点 |
|----------|------|--------|
| 资料开发者 | 开发、维护开发者文档和示例代码 | 提效工具、质量保障 |
| 资料测试者 | 测试资料质量、验证内容正确性 | 自动化测试、检查标准 |
| 技术写作经理 | 管理资料团队、把控质量 | 标准化、可度量、一致性 |
| AI Agent | 接入解决方案执行自动化任务 | Skill/Workflow可发现、可调用 |

### 1.3 核心价值

- **效率提升**：AI Agent主导开发，人力审核，大幅降低重复劳动
- **质量保障**：自动化测试检查，提前发现问题，确保输出一致性
- **知识沉淀**：构建客户专属知识库，持续积累和复用
- **零锁定**：不绑定任何LLM或Agent产品，客户可自由选择接入
- **自进化**：解决方案可根据客户输入自适应修改和扩展

## 二、产品约束与原则

### 2.1 核心约束

| 编号 | 约束 | 说明 |
|------|------|------|
| C-01 | **LLM/Agent无关性** | 解决方案不含任何LLM或Agent产品，仅提供Skill/Workflow定义、规则引擎、检查框架等。客户可接入任何AI Agent（如Claude Code、Cursor、Copilot等） |
| C-02 | **本地优先** | 全部功能应支持本地运行，不强制依赖网络服务。离线可用是基本要求 |
| C-03 | **客户适配** | 不同客户的文档风格、测试标准、格式要求可能完全不同，解决方案必须能根据客户输入自动适配 |
| C-04 | **AI友好** | 所有接口、配置、文档均以AI Agent可理解、可调用的方式设计 |
| C-05 | **AI可维护** | 项目自身文档、架构、计划均支持AI Agent理解和迭代维护 |

### 2.2 设计原则

| 原则 | 说明 |
|------|------|
| 模块化 | 功能拆分为原子化模块，可独立使用、可自由组合 |
| 可扩展 | 支持新增规则、模板、检查项等，无需修改核心框架 |
| 可观测 | 每个执行步骤有完整追踪，可审计、可追溯 |
| 确定性 | 规则类检查必须确定、可复现，模糊性内容由AI处理 |

### 3.2 核心能力一：知识库构建器 (Knowledge Builder)

#### 3.2.1 功能描述

每个客户团队都有其独有的文档风格、测试标准、规格要求和模板。知识库构建器负责分析客户输入，生成该客户专属的解决方案配置。

#### 3.2.2 输入

| 输入类型 | 示例 | 格式 |
|----------|------|------|
| 源文档 | API参考文档、开发指南、元服务指南 | Markdown / HTML / 内部格式 |
| SDK接口声明 | d.ts 类型声明文件 | TypeScript / 其他语言 |
| 示例代码工程 | sampleCode、codelab | 工程目录 / ZIP |
| 测试标准/用例 | 文档质量checklist、测试用例 | XLSX / JSON / YAML |
| 风格规范 | 术语表、禁用词、语气要求 | Markdown / 文本 |
| 模板文件 | 文档章节模板、API参考模板 | Markdown / Handlebars / YAML |

#### 3.2.3 输出

| 输出 | 说明 |
|------|------|
| 规则集 | 格式/风格/内容检查规则（可被Vale等工具执行） |
| 模板库 | 各类文档的标准模板 |
| 知识图谱 | 术语表、API接口与文档的关系映射 |
| 检查清单 | 质量检查项、必选/可选章节等 |
| 配置清单 | 该客户解决方案的完整配置文件 |

#### 3.2.4 关键设计点

- 规则分为**确定性规则**（格式、标点、结构等，由规则引擎执行）和**模糊性规则**（术语一致性、描述清晰性等，由AI辅助判断）
- 支持从客户现有文档中**自动提取风格特征**（标题层级习惯、代码格式、常用句式等）
- 支持**增量更新**：客户新增或修改规范后，可增量更新知识库

### 3.3 核心能力二：开发 (Develop)

#### 3.3.1 功能描述

在已有知识库基础上，根据用户需求生成新的文档内容或修改已有内容，确保输出满足客户的风格、模板和测试标准。

#### 3.3.2 流程

```
用户输入需求（新增/修改某章节或内容）
    │
    ▼
AI Agent 理解需求，从知识库获取相关模板/规则/上下文
    │
    ├── 所需技能：模板匹配器、内容生成器、示例代码生成器
    │
    ▼
生成初版内容
    │
    ▼
自动检查（格式/风格/结构/完整性等）
    │
    ├── 不通过 → 自动修正 → 重新检查
    │
    ▼
输出交付件 → 人工审核 → 审核通过/修改 → 定稿
```

#### 3.3.3 输入/输出

| 项目 | 内容 |
|------|------|
| 输入 | 需求描述（自然语言）、参考信息（可选） |
| 输出 | 符合客户模板/风格的文档章节/完整文档 / ArkTS工程代码 |

### 3.4 核心能力三：测试 (Test)

#### 3.4.1 功能描述

对文档和示例代码进行自动化质量检查，确保满足客户的测试标准。

#### 3.4.2 检查类型

| 检查类型 | 检查项 | 执行方式 |
|----------|--------|----------|
| 格式检查 | 标题层级、标点符号、段落长度、敏感信息 | 规则引擎（如Vale） |
| 风格检查 | 术语使用、禁用词、语气一致性 | 规则引擎 + AI辅助 |
| 结构检查 | 必选章节完整性、章节顺序 | 规则引擎 |
| 内容检查 | 描述清晰性、步骤完整性、场景覆盖 | AI辅助 + 人工确认 |
| 代码检查 | 编译通过、无废弃API、无警告 | 编译工具链 |
| 一致性检查 | 跨文档术语一致性、版本配套一致性 | 规则引擎 |

#### 3.4.3 输出

检查报告（结构化JSON），包含：
- 每项检查的状态（通过/不通过/需人工确认）
- 问题位置（文件/行号）
- 规范依据
- 修改建议

### 3.5 核心能力四：维护 (Maintain)

#### 3.5.1 功能描述

定时或按需检查已有内容是否仍满足最新规格，及时发现因外部变更引入的问题。

#### 3.5.2 场景

| 场景 | 说明 |
|------|------|
| 周期性全量巡检 | 按周/月对全部已有文档和示例工程进行检查 |
| 增量变更检查 | 客户某领域内容变更后（如SDK升级），检查受影响的文档和示例 |
| 版本配套检查 | 跨仓库的版本信息一致性 |

#### 3.5.3 输出

- 维护报告（与测试报告格式一致）
- 变更影响分析（哪些文档/工程需要更新）

### 3.6 核心能力五：问题解决 (Issue Resolution)

#### 3.6.1 功能描述

根据测试或客户反馈的问题单，进行定向分析、修复或判定。

#### 3.6.2 流程

```
收到问题单
    │
    ▼
解析问题描述，定位问题文件和位置
    │
    ├── 判断是否为真问题
    │   ├── 否 → 引用知识库证据，输出非问题判定
    │   └── 是 → 执行修复
    │           │
    │           ▼
    │       自动修复（满足模板/标准）
    │           │
    │           ▼
    │       验证修复结果
    │           │
    │           ▼
    │       输出修复方案 → 人工审核
    │
    ▼
关闭问题单
```

### 3.7 核心能力六：可扩展性 / 自进化 (Extensibility)

#### 3.7.1 功能描述

客户的风格、规格、模板、测试标准可能随时变更或新增，解决方案需支持**零代码或低代码**的扩展方式。

#### 3.7.2 扩展方式

| 扩展类型 | 方式 | 示例 |
|----------|------|------|
| 新增规则 | 添加规则配置文件 | 新增"禁止使用XXX术语"规则 |
| 新增模板 | 添加模板文件 | 新增"错误码章节模板" |
| 新增检查项 | 配置文件新增检查项 | 新增"图片ALT文本检查" |
| 新增Skill | Skill目录下新增Skill定义 | 新增"设备差异表生成器" |
| 修改知识库 | 重新运行知识库构建器 | 客户更新了测试标准后增量更新 |

## 五、非功能需求

### 5.1 AI友好性

| 需求 | 说明 |
|------|------|
| Skill自描述 | 每个Skill包含`skill.yaml`，声明输入/输出/依赖/副作用 |
| 项目自文档 | 项目架构文档、README、开发计划、进度记录均以AI可解析的格式维护 |
| 配置可读 | 所有配置使用YAML/JSON/Markdown等AI易解析的格式 |
| 上下文恢复 | 维护开发日志和进度记录，支持AI Agent中断后恢复 |

### 5.2 AI可维护性

| 需求 | 说明 |
|------|------|
| 项目架构文档 | 清晰的目录结构说明、模块职责说明 |
| 开发迭代计划 | 短期/长期计划文档，可按计划逐步推进 |
| 进度记录 | 持续记录开发进度、决策记录、待办事项 |
| 变更日志 | 记录每次变更的内容、原因、影响范围 |

### 5.3 离线可用

| 需求 | 说明 |
|------|------|
| 无网络依赖 | 核心功能不依赖外部网络服务 |
| 本地工具链 | 规则引擎、模板引擎、解析器等均为本地可执行 |
| 离线知识库 | 知识库存储在本地文件系统 |

### 5.4 安全性

| 需求 | 说明 |
|------|------|
| 数据隔离 | 不同客户的知识库/配置相互隔离 |
| 路径安全 | 所有文件操作有路径验证，防止路径遍历 |
| 配置安全 | 敏感配置不硬编码 |
