## 一、总体设计

### 1.1 设计目标

- 构建一套**模块化、可扩展、AI友好**的解决方案系统
- 支持客户**零代码/低代码**接入和定制
- 所有核心能力**本地可运行**，不依赖网络
- 以**Skill体系**为核心，AI Agent可通过标准化接口调用

### 1.2 技术选型

| 层级 | 技术选型 | 理由 |
|------|----------|------|
| 核心语言 | Python 3.11+ | AI Agent生态丰富，跨平台，脚本友好 |
| 规则引擎 | Vale (文档Lint) | 业界标准文档检查工具，规则可定制，本地运行 |
| 模板引擎 | Jinja2 | Python生态，功能强大，支持继承/宏 |
| 配置文件 | YAML + JSON Schema | AI易解析，支持校验 |
| 文档解析 | markdown-it-py + tree-sitter | MD解析 + 代码解析 |
| 数据存储 | 本地文件系统 + Git | 简单可靠，支持版本管理 |
| 可观测性 | STOP协议 (自定义实现) | Skill执行的标准化追踪 |

## 二、Skill 体系设计

### 2.1 Skill 定义规范

每个 Skill 通过 `skill.yaml` 文件自描述，格式如下：

```yaml
# skill.yaml
name: quality-checker                # Skill 唯一名称
version: 1.0.0                       # 版本
description: 文档质量检查器，支持格式/风格/结构/代码检查

inputs:                              # 输入声明
  - name: target_path               # 参数名
    type: path                      # 类型: path/string/object/array
    description: 待检查的文件或目录路径
    required: true
  - name: check_type
    type: string
    description: 检查类型 (all/format/style/structure/code)
    required: false
    default: all

outputs:                             # 输出声明
  - name: report
    type: object
    description: 检查报告 (符合 check-report.schema.json)
    schema: check-report.schema.json

dependencies:                        # 依赖的工具/Skill
  tools:
    - vale                          # 依赖 Vale 规则引擎
  skills: []                         # 依赖的其他 Skill

observability:                       # 可观测性
  trace: true                        # 是否记录执行追踪
  logs: true                         # 是否记录日志
```

### 2.3 原子 Skill 详细设计

#### 2.3.1 knowledge-builder (知识库构建器)

**用途**：分析客户输入（源文档、测试标准、模板等），生成客户专属知识库

**输入**：
- `input_dir`：客户提供的所有源材料目录
- `customer_name`：客户名称/标识

**处理流程**：
1. 扫描输入目录，识别文件类型（MD / d.ts / YAML / XLSX / JSON）
2. 解析源文档提取风格特征（标题层级习惯、代码块格式、术语使用）
3. 解析测试标准/checklist生成规则集
4. 解析模板文件注册到模板库
5. 输出知识库配置

**输出**：
- `knowledge/config.yaml`：知识库配置
- `knowledge/rules/`：生成的规则集
- `knowledge/templates/`：注册的模板
- `knowledge/glossary/`：提取的术语表

**技术要点**：
- Markdown解析使用 `markdown-it-py` 提取标题层级、章节结构
- d.ts解析使用 `tree-sitter-typescript` 提取接口声明
- XLSX解析使用 `openpyxl` 提取测试用例
- 规则生成使用预定义模板 + 参数填充

#### 2.3.2 quality-checker (质量检查器)

**用途**：对文档/代码执行质量检查

**输入**：
- `target_path`：检查目标
- `check_type`：检查类型
- `knowledge_dir`：知识库目录（可选，默认使用当前知识库）

**处理流程**：
1. 加载知识库中的规则集和检查清单
2. 根据check_type选择检查器组合
3. 执行检查
4. 生成检查报告

**检查器组合**：

| check_type | 包含的检查器 |
|------------|-------------|
| format | 格式检查器 (Vale) |
| style | 格式检查器 + 风格检查器 |
| structure | 结构检查器 |
| code | 代码检查器 (编译) |
| consistency | 一致性检查器 |
| all | 全部检查器 |

**输出**：检查报告（符合 `check-report.schema.json`）

#### 2.3.3 content-generator (内容生成器)

**用途**：基于模板和知识库生成文档内容

**输入**：
- `template_name`：使用的模板名称
- `params`：填充模板的参数
- `knowledge_dir`：知识库目录

**处理流程**：
1. 加载指定模板
2. 验证参数完整性（必填项检查）
3. 渲染模板内容
4. 自动运行质量检查
5. 返回生成结果 + 检查报告

**输出**：
- `content`：生成的文档内容
- `report`：质量检查报告

#### 2.3.4 issue-resolver (问题解决器)

**用途**：根据问题单定位并修复问题

**输入**：
- `issue_description`：问题单描述
- `target_path`：问题文件路径（可选）
- `knowledge_dir`：知识库目录

**处理流程**：
1. 解析问题描述，提取关键信息（问题类型、位置、期望）
2. 定位问题文件（如未指定则自动搜索）
3. 判断是否为真问题（引用知识库规则）
4. 如为问题：执行修复 → 质量检查验证 → 输出修复方案
5. 如非问题：输出非问题判定 + 知识库证据

**输出**：
- `is_issue`：是否是真问题
- `fix_suggestion`：修复建议（如为问题）
- `evidence`：判定依据
- `report`：修复后的质量检查报告（如已修复）

#### 2.3.5 maintenance-scanner (维护扫描器)

**用途**：周期扫描已有内容，检查是否符合最新规格

**输入**：
- `scan_path`：待扫描的文档/工程目录
- `knowledge_dir`：知识库目录
- `mode`：扫描模式 (full/incremental)

**处理流程**：
1. 加载知识库最新规则
2. 扫描所有文件执行质量检查
3. 对比上次扫描结果，识别新增/修复/遗留问题
4. 生成维护报告

**输出**：
- `report`：检查报告
- `diff`：与上次扫描的差异
- `summary`：问题统计和趋势

### 2.4 综合 Workflow 设计

综合 Workflow 使用 YAML 定义多个 Skill 的编排顺序：

```yaml
# workflows/full-development.yaml
name: full-development
description: 全流程资料开发工作流
version: 1.0.0

steps:
  - name: 需求理解
    type: prompt                    # AI Agent 需要与用户交互的步骤
    prompt_template: |
      用户需求：{user_request}
      请向用户确认以下信息：
      1. 需要新增还是修改？
      2. 涉及哪些交付件？
      3. 是否有参考文档？
    output: requirements

  - name: 知识库加载
    skill: knowledge-builder
    params:
      knowledge_dir: "{knowledge_dir}"

  - name: 模板匹配
    skill: template-match          # 根据需求匹配合适的模板
    params:
      requirements: "{requirements}"
    output: template

  - name: 内容生成
    skill: content-generator
    params:
      template: "{template}"
      params: "{requirements}"
    output: draft_content

  - name: 质量检查
    skill: quality-checker
    params:
      target: "{draft_content}"
      check_type: all
    output: report

  - name: 问题修正
    condition: report.has_issues   # 有条件执行
    skill: content-generator
    params:
      template: "{template}"
      params: "{requirements}"
      fix_issues: "{report.issues}"
    output: final_content

  - name: 输出交付件
    type: output
    format: 文件保存 + 检查报告
    output_path: "{output_dir}/{generated_file}"
```

### 3.3 规则集设计

规则分为两级：

**一级：确定性规则（由 Vale / 规则引擎执行）**

```yaml
# rules/custom/format-rules.yaml
rules:
  - id: "heading-level"
    name: "标题层级规则"
    description: "一级标题只能有一个，后续标题必须按层级递增"
    type: "vale"  # 由Vale执行
    severity: "error"
    vale_rule: "DocsStyle.HeadingHierarchy"

  - id: "terminology-check"
    name: "术语检查"
    description: "术语使用必须与术语表一致"
    type: "vale"
    severity: "warning"
    vale_rule: "Custom.Terminology"

  - id: "required-sections"
    name: "必选章节检查"
    description: "文档必须包含所有必选章节"
    type: "custom"  # 由自定义检查器执行
    severity: "error"
    check_function: "structure_checker.check_required_sections"
    params:
      required: ["简介", "开发指导", "API参考", "常见问题"]
```

**二级：模糊性规则（由 AI Agent + 人工确认）**

```yaml
# rules/custom/ai-rules.yaml
rules:
  - id: "description-clarity"
    name: "描述清晰性"
    description: "步骤描述必须清晰，无歧义"

    severity: "suggestion"
    check_prompt: |
      检查以下文档内容中的步骤描述是否清晰：
      1. 每个步骤是否有明确的执行主体？
      2. 每个步骤是否有可操作的动作？

    name: "场景覆盖完整性"
    description: "文档应覆盖所有常用场景"
    type: "ai-review"
    severity: "suggestion"

      分析文档是否覆盖了以下场景：
      - 正常流程
```

## 五、引擎层设计

### 5.1 规则引擎适配层 (Vale集成)

```python
# engine/rule_engine/vale_adapter.py
"""
Vale 规则引擎适配器
负责：执行 Vale 检查、解析 Vale 输出为统一格式
"""

class ValeAdapter:
    def __init__(self, vale_bin: str, config_path: str):
        self.vale_bin = vale_bin
        self.config_path = config_path
```
